### Coordinator-owned execution contract

The runner receives two programmatic inputs from trusted Host code:

1. a validated registration fixed outside Agent-controlled MCP input;
2. an M5-001 `ExternalAdapterRequest`.

The registration contains:

- the expected adapter ID, name, and version;
- one explicit argv array whose first entry is the executable;
- an allowlist of source-system names;
- an allowlist of credential environment-variable names;
- timeout, stdout-byte, and stderr-byte limits.

It contains no credential values. The runner builds a fresh child environment
from a small documented operating-system baseline plus only the configured
credential names found in the Host environment. It must not spread the Host
environment into the child.

The runner executes the argv directly with `shell: false`, writes exactly one
validated JSON request to stdin, accepts exactly one JSON response on stdout,
drains but never returns/logs/persists stderr, and terminates the child on
timeout or either output limit. Its public errors expose only bounded stable
codes and safe numeric exit metadata; they do not include argv, environment
names/values, stdout, stderr, response content, or document excerpts.

Before normalization it enforces:

- request `adapterId`, registration identity, and response identity match;
- every request ID has exactly one result and no extra result exists;
- result source type matches its request;
- request and result source systems are allowlisted and a result cannot change
  source system while canonicalizing locator/URI;
- all M5-001 runtime refinements pass.

Protocol or infrastructure failure rejects the entire invocation. Structured
`not_found`, `permission_denied`, `unsupported`, and adapter `error` results
remain valid evidence-availability outcomes.

### Coordinator-owned normalization contract

Available results become deterministic `EvidenceItem` records:

- core ID generated by Change Trace from stable adapter/request/source
  identity;
- type `document`;
- canonical result source and retrieval time;
- SHA-256 of the complete pre-redaction excerpt, or `null` when the adapter
  reports truncation;
- related change IDs and selection reason copied from the matching request;
- secret-like content redacted before the excerpt leaves the runner;
- trust forced to `untrusted_external`;
- truncation metadata retained with the final excerpt length;
- strict `externalProvenance` containing the configured adapter identity,
  source type, title, and nullable source update time.

Unavailable results become `MissingEvidence` in request order:

- `not_found` -> `not_found`;
- `permission_denied` -> `inaccessible`;
- `unsupported` -> `unsupported`;
- adapter `error` -> `inaccessible`.

Diagnostic messages are secret-redacted before becoming bounded reasons.

The returned `ExternalEvidenceCollection` contains the configured adapter
identity, evidence items, and missing evidence. It enforces
`untrusted_external`, external provenance, adapter match, and a combined
maximum of 100 outcomes.

### Review findings

- The runner decodes stdout with `Buffer.toString("utf8")`. Node replaces
  malformed byte sequences with U+FFFD, so invalid UTF-8 embedded inside an
  otherwise valid JSON string can pass `JSON.parse` and the response schema.
  Adapter protocol JSON must be valid UTF-8; decode with a fatal UTF-8 decoder
  and return the existing safe `invalid_response` code without exposing
  content. Add a binary-output fixture and regression assertion.
- The Worker handoff records implementation commit
  `e38ccd06a790add8515d87355182f2e97ef5cd27`, but the actual repository object
  is `e38ccd0c1a16763869984ed95662dc91c2319558`. Correct the durable handoff and
  record the new follow-up commit/head exactly.
- The disclosed Windows bootstrap environment was independently reproduced:
  Node injects the documented system/user/session bootstrap variables even
  when given a smaller environment object. The focused test confirms arbitrary
  Host variables and non-allowlisted credential values remain absent. This is
  accepted as a documented platform boundary, not a review finding.
